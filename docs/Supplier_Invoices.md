# חשבוניות ספקים

אזור להעלאת חשבוניות שמגיעות מספקים ושצריך לשלם עליהן.
כל חשבונית משויכת ללקוח, ויש לה סכום ותנאי תשלום. היא מוצגת בחודש שבו התשלום אמור להתבצע, ואפשר לסמן עליה "שולם".

## נתיבים

| נתיב | תיאור |
|---|---|
| `/app/invoices` | עמוד החשבוניות |
| `GET /api/invoices` | רשימת חשבוניות, לקוחות פעילים וספקים לטופס |
| `POST /api/invoices` | יצירת חשבונית (multipart, כולל קובץ) |
| `POST /api/invoices/<id>` | עריכת חשבונית. קובץ חדש מחליף את הקודם |
| `POST /api/invoices/<id>/toggle_paid` | סימון או ביטול "שולם" (`{"is_paid": true}`) |
| `POST /api/invoices/<id>/delete` | מחיקת החשבונית והקובץ שלה |
| `GET /api/invoices/<id>/file?inline=1` | צפייה בקובץ. בלי `inline` הקובץ יורד |
| `GET /api/invoices/export` | ייצוא לאקסל (ראו למטה) |
| `POST /api/invoices/extract` | קריאת קובץ חשבונית עם AI והחזרת שדות למילוי. לא שומר דבר |

## חישוב מועד התשלום

| תנאי | ערך | חישוב |
|---|---|---|
| מיידי | `immediate` | תאריך החשבונית |
| שוטף+30 / 60 / 90 / 120 | `net30` ... `net120` | סוף החודש של תאריך החשבונית ועוד N ימים |

דוגמה: חשבונית מ-1.10 עם שוטף+60 תגיע ל-31.10 ועוד 60 יום, כלומר 30.12. לכן היא תופיע בדצמבר.

השרת מחשב את `due_date` בכל יצירה ובכל עריכה (`_compute_invoice_due_date` ב-`app.py`). הטופס מציג תצוגה מקדימה לפי אותו כלל.

## ממשק

- **סיכום בראש העמוד:** סך הכול בחשבוניות פתוחות, מספר החשבוניות הפתוחות, הסכום הפתוח לחודש הנוכחי והסכום הפתוח שעבר מועד התשלום שלו.
- **רשימה מקובצת לפי חודש התשלום:** לכל חודש מוצגים הסכום הפתוח והסכום ששולם. ליד כל חשבונית יש Checkbox "שולם", ושורה ששולמה מוצגת באפור.
- **סינון:** פתוחות / שולמו / הכול (ברירת המחדל: פתוחות), לפי לקוח, וחיפוש טקסט.
- **ספק:** אפשר לבחור מרשימת הספקים הקיימת או להקליד שם חופשי.

## ייצוא לאקסל

- כפתור **"ייצוא לאקסל"** בראש העמוד מייצא את כל החודשים, עם גיליון נפרד לכל חודש תשלום.
- קישור **"אקסל"** בכותרת של כל חודש מייצא רק את החודש הזה.
- הייצוא מכבד את הסינון שנבחר בעמוד (סטטוס ולקוח).
- פרמטרים: `month=YYYY-MM` (אופציונלי), `status=open|paid|all`, `client_id`.
- בכל גיליון יש: ספק, מספר חשבונית, לקוח, סכום, תאריך חשבונית, תנאי תשלום, מועד תשלום, סטטוס, תאריך תשלום והערות. בסוף הגיליון מופיעים סה״כ פתוח, סה״כ שולם וסה״כ. שורות ששולמו מסומנות באפור, והגיליון מוצג מימין לשמאל.

## מילוי אוטומטי מהקובץ (OpenAI)

כשבוחרים קובץ בטופס של חשבונית חדשה, הקובץ נשלח ל-`/api/invoices/extract`. השרת שולח אותו ל-OpenAI (Chat Completions עם JSON Schema) ומחזיר ספק, מספר חשבונית, סכום כולל מע״מ ותאריך הנפקה. אם בחשבונית מוזכר בבירור לקוח מוכר, גם הוא מוחזר.

- הקריאה עובדת על PDF, כולל סריקות, ועל תמונות.
- רשימת הספקים והלקוחות הקיימים נשלחת למודל, כדי שיחזיר שם קיים כשיש התאמה.
- **הטופס לא דורס שדות שכבר מולאו**, חוץ מהתאריך: שדה הקובץ הוא הראשון בטופס, ולכן בשלב הזה התאריך עדיין מכיל את ברירת המחדל של היום.
- המשתמש רואה הודעה "הפרטים מולאו אוטומטית", וצריך לבדוק את הפרטים ולשמור בעצמו.
- בעריכה של חשבונית קיימת אין מילוי אוטומטי.

### הגדרה

| משתנה סביבה | תיאור |
|---|---|
| `OPENAI_API_KEY` | חובה. בלי המפתח הפיצ'ר כבוי והטופס עובד ידנית כרגיל |
| `OPENAI_INVOICE_MODEL` | אופציונלי. ברירת המחדל היא `gpt-4.1-mini`. צריך מודל שתומך בקלט של קבצים ותמונות |

- הגודל המקסימלי לקריאה אוטומטית הוא 20MB, וזמן ההמתנה המקסימלי לתשובה הוא 60 שניות.
- הקריאה ל-API נעשית עם `urllib` מהספרייה הסטנדרטית, בלי תלות נוספת.

## אחסון

- **פיתוח (JSON):** הרשומות נשמרות ב-`supplier_invoices.json`, והקבצים ב-`uploads/approvals/invoices/<id>/`.
- **פרודקשן (PostgreSQL):** הרשומות נשמרות בטבלה `supplier_invoices` (`id` ו-`data` מסוג JSONB), שנוצרת בשימוש הראשון. תוכן הקבצים נשמר בטבלה `approval_file_blobs`, אותה טבלה שמשמשת את אישור החומרים, כדי שהקבצים לא יימחקו בדיפלוי.
- הגודל המקסימלי של קובץ במצב DB הוא 50MB.

## הרשאות

`"/invoices": "מנהל"` ב-`permissions_db.json`. רק מנהל ואדמין רשאים לגשת. `load_permissions` מוסיף את המפתח אם הוא חסר.
ההרשאה נאכפת בשרת בכל נקודות הקצה. משתמש אחר מקבל `403`, והעמוד מציג לו "אין הרשאה".
